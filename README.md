# AI Inventory Trend & Replenishment Assistant (MVP)

Production-style MVP for SMB inventory planning that combines internal demand history with external trend signals to produce daily replenishment recommendations.

## What it does

- Ingests data from CSV/XLSX files (and includes a SQL ingestion utility).
- Auto-normalizes common column aliases and gracefully handles missing fields.
- Cleans, deduplicates, and aggregates product demand.
- Builds demand + trend features with configurable weighting.
- Estimates trend persistence, variability, and likely duration.
- Forecasts 7/14/30-day demand and stock coverage.
- Detects stockout and overstock risk.
- Generates actionable recommendations:
  - `urgent reorder`
  - `increase order`
  - `decrease order`
  - `maintain`
- Produces daily report outputs:
  - CSV
  - Excel
  - manager summary text
- Exposes FastAPI endpoints and a Streamlit dashboard.

## Trend weighting (configurable)

Configured in `app/config.py`:

```python
adjusted_demand_score =
0.35 * historical_demand_score +
0.20 * market_trend_score +
0.15 * competitor_trend_score +
0.10 * social_trend_score +
0.10 * seasonality_score +
0.10 * trend_persistence_score
```

This score is then multiplied by `trend_impact_multiplier` from persistence analysis.

## Trend persistence logic (MVP heuristic)

`app/services/trend_persistence.py` classifies trends using:

- signal slope across the last 28 days
- direction (rising/falling/stable)
- variability (std dev)
- strength (recent average minus baseline)
- seasonality alignment

Outputs per product:

- `expected_trend_duration_days`
- `trend_variability_score`
- `trend_confidence`
- `trend_type`
- `trend_impact_multiplier`

This is intentionally lightweight and pluggable for future ML models.

## Quick start

### 1) Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2) Run API

```bash
uvicorn app.main:app --reload
```

On startup, database tables are created. If no product data exists, a demo pipeline run is executed automatically.

### 3) Generate / refresh demo run (optional)

```bash
curl -X POST http://127.0.0.1:8000/run/demo
```

### 4) Run dashboard

```bash
streamlit run app/dashboard/streamlit_app.py
```

## API endpoints

- `POST /upload/excel` – upload sales/inventory/products/trends files.
- `POST /connect/sql` – MVP placeholder for SQL connector contract.
- `GET /products`
- `GET /recommendations`
- `GET /report/daily`
- `GET /product/{product_id}`
- `GET /trends/{product_id}`
- `POST /run/demo`

## Input data

Sample input files are included in `data/sample/`:

- `products.csv`
- `sales.csv`
- `inventory.csv`
- `trends.csv`

If files are not provided, synthetic demo datasets are auto-generated by `demo_data.py`.

## Environment variables

Optional overrides:

- `DATABASE_URL` (default `sqlite:///./inventory_ai.db`)
- `DATA_DIR` (default `data`)
- `REPORT_DIR` (default `data/reports`)

## Testing

```bash
pytest -q
```

## Notes and assumptions

- Forecasting is implemented as rolling-demand baseline + trend-adjusted multiplier for MVP reliability/simplicity.
- Pipeline is designed to be replaced with advanced forecasting (ARIMA/Prophet/XGBoost) later.
- SQL ingestion utility exists in `ingestion.py` and can be wired directly to `/connect/sql` in next iteration.
